# Дашборд анализа вегетационных индексов на территории гарей

**Полное описание готового проекта: постановка задачи, ход работы и итоговый продукт**

Иркутская область · пожары 2005 года · данные MODIS / Landsat / Sentinel-2

---

## 1. О чём проект и зачем он нужен

Это интерактивное веб-приложение (дашборд) для анализа состояния растительности на
территориях лесных пожаров (гарей). На примере пожаров **2005 года в Иркутской
области** приложение показывает, как менялась растительность **до и после пожара** по
разным вегетационным индексам, и позволяет исследователю наглядно оценить степень
повреждения и ход восстановления.

**Кому и зачем.** Такой инструмент нужен специалистам по дистанционному зондированию,
лесному хозяйству и экологии: вместо того чтобы вручную открывать десятки растровых
снимков и таблиц, пользователь работает с единым интерактивным экраном — кликает на
гарь на карте и сразу видит всю аналитику по ней.

**Ключевая идея.** Пользователь выбирает пожар прямо на карте, и **все графики и снимки
мгновенно пересчитываются под выбранную гарь** (принцип кросс-фильтрации).

## 2. Исходные данные

Проект построен на реальных геопространственных данных:

| Данные | Что это | Формат |
|--------|---------|--------|
| Полигоны пожаров | 159 гарей 2005 г. с атрибутами (площадь, даты, лесничество) | Shapefile → GeoJSON |
| Растры вегетационных индексов | 728 снимков (.tif) по 159 гарям за разные годы | GeoTIFF |
| Ряды вегетационных индексов | Значения индексов по годам относительно пожара | CSV |
| Площади растительного покрова | Динамика типов покрова по годам (классы MODIS) | CSV |
| Классы NDVI по территории | Распределение площадей по классам NDVI за каждый год | CSV |
| Лесничества | Границы лесничеств | GeoJSON |
| MODIS MCD12C1 | Растровые данные типов земного покрова (IGBP) | GeoTIFF |

**Вегетационные индексы** (7 штук), каждый показывает свою характеристику:

- **NDVI** — состояние растительности (выше = здоровее);
- **EVI** — состояние густой растительности;
- **SAVI** — состояние разреженной растительности (с поправкой на почву);
- **NBR** — повреждение пожаром (выше = сильнее);
- **NBR2** — влажность после пожара;
- **BAI** — признаки выгоревшей поверхности (выше = сильнее выгорело);
- **NDWI** — влагосодержание растений.

> Важно: для NDVI/EVI/SAVI бóльшее значение = «здоровее», а для NBR/BAI наоборот —
> бóльшее значение = «сильнее повреждение». Это учтено в цветовой раскраске всех
> графиков и легенд.

## 3. Технологический стек и архитектура

Приложение состоит из двух частей — бэкенда (обработка данных) и фронтенда (интерфейс).

### Бэкенд — Python

- **FastAPI** — REST API-сервер;
- **GeoPandas / rasterio** — работа с геоданными и растрами;
- **Pillow / NumPy** — рендеринг растров в цветные PNG и сборка анимированных GIF;
- самописные цветовые карты (без matplotlib) для раскраски индексов.

Бэкенд читает исходные данные, отдаёт их фронтенду в готовом виде (GeoJSON/JSON),
а тяжёлые растры **на лету** превращает в цветные картинки с геопривязкой.

### Фронтенд — JavaScript / TypeScript

- **Next.js 16 + React 19** — каркас приложения;
- **Leaflet** — интерактивная карта;
- **Recharts** — графики;
- **Tailwind CSS 4** — оформление на семантических токенах (единая тема).

### Схема работы

```
Данные (GeoTIFF/CSV/GeoJSON)
        │
        ▼
  Бэкенд FastAPI  ──►  REST API (GeoJSON, JSON, PNG, GIF)
        │
        ▼
  Фронтенд Next.js  ──►  Карта + графики + галерея снимков
        │
        ▼
     Браузер пользователя
```

### API-эндпоинты

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/fires` | GeoJSON полигонов пожаров |
| GET | `/api/fires/meta` | Метаданные пожаров |
| GET | `/api/lesnichestva` | GeoJSON лесничеств |
| GET | `/api/filters` | Значения для фильтров (из самих данных) |
| GET | `/api/vi/aggregate` | Сводная динамика VI по всем гарям |
| GET | `/api/vi/by-fire/{id}` | Динамика VI для одной гари |
| GET | `/api/vi/multi-fire` | Динамика VI для набора гарей |
| GET | `/api/veg-areas/aggregate` | Динамика растительного покрова (сводно) |
| GET | `/api/veg-areas/by-fire/{id}` | Растительный покров для одной гари |
| GET | `/api/ndvi-areas` | Площади по классам NDVI по территории |
| GET | `/api/raster/available` | Доступные снимки гари (годы, сенсоры, границы) |
| GET | `/api/raster/{id}/{year}/{band}.png` | Цветной растр индекса (PNG) |
| GET | `/api/raster/{id}/{band}.gif` | Анимация снимков по годам (GIF) |

## 4. Что умеет итоговый продукт (функциональность)

### Карта и кросс-фильтрация
- Интерактивная карта Иркутской области с **159 полигонами гарей** и слоем лесничеств.
- **Клик по гари** выбирает её — вся аналитика пересчитывается под неё; повторный клик
  снимает выбор. Можно выбрать несколько гарей.

### Вегетационные индексы прямо на карте
- При выборе одной гари её снимок в выбранном индексе **накладывается на карту как
  геопривязанный слой** по реальным границам растра (карта плавно подлетает к гари).
- Панель управления слоем: включение/выключение, выбор года снимка (год пожара
  помечен), регулировка прозрачности снимка.

### Галерея снимков и анимация
- Снимки гари по всем доступным годам показываются под картой (без обрезки — соседние
  годы можно сравнивать «на глаз»), клик увеличивает снимок.
- Кнопка **«Скачать GIF»** — бэкенд собирает анимацию изменения индекса по годам с
  подписью «индекс · год» в каждом кадре.
- Легенда снимка подписывает смысл низких/высоких значений по каждому индексу.

### Графики
- **Динамика VI** — средний индекс по годам относительно пожара (−5 … +20 лет), с
  затенением допожарной зоны и отметкой года пожара.
- **Чувствительность** — отклонение индекса от допожарного среднего в процентах
  (для BAI знак инвертирован по смыслу повреждения).
- **Динамика растительного покрова** — накопительный график площадей типов покрова
  по годам; сбоку легенда с площадями и долями по наведённому году.
- **Состояние растительности по территории** — распределение площадей по классам
  NDVI за каждый год (общая аналитика).

### Фильтры и сводка
- Выбор индекса, агрегации (median/max/min), периода (до/после/весь), типа
  растительности, диапазона площади, лесничества.
- Сводная полоса статистики: число гарей, площади, значения индекса до/после пожара,
  изменение в год пожара и восстановление.
- Раздел «Выбранные пожары» вверху — с датами событий.

### Оформление
- **Светлая и тёмная темы** с сохранением выбора и применением до первой отрисовки.
- Единый дизайн блоков-карточек, аккуратные анимации при наведении, читаемый шрифт.

## 5. Как выполнялась работа

Проект разрабатывался итеративно, с регулярной проверкой в браузере и учётом замечаний
научного руководителя. Основные этапы (подробный дневник — в `README.md`):

1. **Постановка и проектирование.** Разбор задачи, изучение данных и примеров
   дашбордов, выбор стека, проектирование API и архитектуры.
2. **Базовый функционал.** Конвертация шейпфайлов в GeoJSON, первые эндпоинты,
   интерактивная карта с кросс-фильтрацией, первые графики, панель фильтров.
3. **Ключевая функция — VI на карте.** Геопривязанное наложение снимков индексов на
   карту (пересчёт границ растров в WGS84), панель управления слоем.
4. **Масштабируемость.** Отвязка от жёсткого 2005 года (год пожара вычисляется из
   данных), рекурсивный поиск растров, фильтры и период данных строятся из самих
   данных — структура готова к добавлению новых лет.
5. **Дизайн-система.** Семантические токены темы, карточная компоновка, переработка
   графиков и полосы статистики, светлая/тёмная темы.
6. **Доработка по замечаниям руководителя.** Смысловые названия индексов, корректная
   интерпретация индексов повреждения (NBR/BAI), исправление легенды классов
   растительности по официальной классификации MODIS MCD12C1 (IGBP), единый формат
   чисел, кнопка «Скачать GIF» вместо постоянной анимации, вынос выбранных пожаров с
   датами наверх, новый общий график по классам NDVI, устранение мелких дефектов.
7. **Полировка.** Увеличение читаемости шрифта, устранение пустот в раскладке,
   исправление сортировки классов и подсказок, финальные проверки.

**Проверка качества.** На каждом этапе — проверка типов (`tsc --noEmit`), отсутствие
ошибок в консоли браузера и прогон интерфейса в headless-браузере (Playwright/Chromium):
выбор гари, кросс-фильтрация, наложение снимков, галерея, скачивание GIF, переключение
темы.

## 6. Итоговый продукт

Готовое, работающее веб-приложение, которое:

- отображает **159 реальных гарей** на интерактивной карте с кросс-фильтрацией;
- накладывает снимки **7 вегетационных индексов** прямо на карту с геопривязкой;
- показывает **4 типа графиков** аналитики, пересчитываемых под выбранную гарь;
- даёт **галерею снимков по годам** и экспорт анимации в GIF;
- поддерживает **гибкую фильтрацию**, **светлую/тёмную темы** и аккуратный,
  читаемый интерфейс;
- построен на **реальных данных** и **структурно готов к расширению** (другие годы,
  сенсоры, индексы) без переписывания кода.

Проект развёрнут локально (бэкенд на `:8000`, фронтенд на `:3000`), проходит проверку
типов и сборку без ошибок, протестирован в браузере.

## 7. Как запустить

**Бэкенд:**
```bash
cd backend
pip install -r requirements.txt
python main.py           # API на http://localhost:8000
```

**Фронтенд:**
```bash
cd frontend
npm install
npm run dev              # приложение на http://localhost:3000
```

> Растровые снимки (папка `Data/fire_rasters/`, ~890 МБ) не хранятся в репозитории
> из-за размера — их нужно распаковать из архива (ссылка в шапке приложения) в папку
> `Data/fire_rasters/` и перезапустить бэкенд. Он находит снимки на любой вложенности.
